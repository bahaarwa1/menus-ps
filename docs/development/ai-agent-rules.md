# Menus.ps — AI Agent Engineering & Development Operating Rules

قواعد العمل الإلزامية لأي مهندس ذكاء اصطناعي (AI Agent) يعمل على تطوير وصيانة منصة Menus.ps.

---

## القواعد الـ 13 الإلزامية:

### 1. قراءة الـ Skill أولاً (Read the Skill First)
قبل تنفيذ أي مهمة أو كتابة أي سطر كود، يجب على الوكيل استعراض وقراءة ملف الـ Skill الخاص بالمشروع في `.agents/skills/menus.ps-project-skill/SKILL.md` لاستحضار كافة مبادئ المشروع المعمارية والتصميمية.

### 2. فهم المعمارية الحالية (Understand Current Architecture)
استيعاب أن المشروع مبني بـ Next.js 14.2 App Router مع React 18 و Tailwind CSS و TypeScript، ومعرفة دور كل مسار (`/`، `/m`، `/staff`، `/demo/*`).

### 3. البحث في الكود المرتبط بالمهمة (Locate Related Code First)
استخدام أدوات البحث (`grep_search`، `find_by_name`) للعثور على الملفات والوظائف المعنية قبل كتابة أي كود جديد.

### 4. عدم إنشاء أنظمة موازية (No Parallel Systems)
ممنوع نهائياً كتابة نظام جديد وموازٍ إذا كان هناك نظام أو ملف يخدم نفس الغرض. يتم البناء فوق الموجود وتطويره بشكل تراكمي.

### 5. إعادة استخدام المكونات والوظائف (Reuse Existing Components)
إعادة استخدام الكومبوننتات الموجودة في `components/common/` (مثل `<Logo />`) و `components/layout/` وعدم تكرار كتابة مكونات مكررة.

### 6. عدم كسر الميزات القائمة (Never Break Existing Features)
أي تعديل أو ميزة جديدة يجب أن تحافظ على استقرار الصفحات الحالية. ممنوع كسر مسار طلب الزبون أو شاشة المطبخ.

### 7. عدم حذف ملفات أو وظائف دون مبرر صريح (No Destructive Deletions)
ممنوع حذف أي ملف أو وظيفة أو مسار إلا إذا كان هناك طلب صريح وواضح مع توثيق البديل.

### 8. فحص الـ Schema قبل أي تعديل لقاعدة البيانات (Inspect Schema Before Modifying DB)
مراجعة ملف `docs/database/schema-design.md` وواجهات `@/data/demo-data.ts` قبل إضافة أو تعديل أي حقل لتجنب كسر توافق البيانات.

### 9. فحص الـ APIs الموجودة قبل إنشاء واجهات جديدة (Audit Existing APIs)
مراجعة ملف `docs/api/api-specifications.md` وتنسيق الـ Endpoints لتتبع نفس أسلوب REST / Server Actions المعتمد.

### 10. فحص المكونات قبل إنشاء مكونات جديدة (Audit Components Before Creation)
التحقق من المكونات الحالية ومكتبة الأيقونات (Lucide React) لضمان اتساق الـ Design System.

### 11. تشغيل الفحص والاختبارات بعد التعديل (Run Lint & Build Checks)
تشغيل `npm run lint` أو فحص التايب سكريبت بعد كل تعديل للتأكد من عدم وجود أخطاء صامتة قبل تسليم المهمة.

### 12. إصلاح أي خطأ ناتج فوراً (Fix Errors Immediately)
في حال ظهور أي خطأ في البناء أو العرض، يجب تحليله وإصلاحه ذاتياً فوراً دون تجاهله.

### 13. تقديم ملخص واضح ومهني لما تم تغييره (Provide Clear Change Summary)
شرح التعديلات المنجزة للمستخدم باللغة العربية بدقة ووضوح، مع ذكر أسباب التغيير والملفات التي تم تعديلها ورابط التجربة.

## مبادئ خاصة بتجربة مستخدم Menus.ps:
- **اللغة**: عربية نقية ومريحة ومناسبة للمطاعم المحلية.
- **التسعير**: الشيكل الفلسطيني (`₪`).
- **المطبخ**: خالي تماماً من الأرقام المالية.
- **المنيو**: سريع، خفيف، بدون نوافذ منبثقة معطلة، الإضافة مباشرة `+ أضف` -> `[-] qty [+]`.
- **اللوجو**: استخدام شعار MENUS كصورة مستقلة دون كتابة نصوص إضافية بجانبها.
- **الأبعاد**: الالتزام بنسبة `[zoom:0.8]` في شاشات `/m` و `/staff` و `/demo/orders`.
