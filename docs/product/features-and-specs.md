## 2. تحليل الديون والمشاكل التقنية (Technical Debt & Vulnerabilities)

### 2.1 الديون التقنية (Technical Debt)
1. **الاعتماد على Mock Data فقط**: البيانات حالياً في `data/demo-data.ts` مخزنة في الذاكرة (In-Memory). أي تعديل على صنف أو طلب يزول بمجرد عمل Refresh للصفحة.
2. **غياب طبقة الـ APIs**: لا يوجد مسار `/app/api` حتى الآن؛ كل العمليات تجري كـ Client Mutations عبر `useState`.
3. **تحذيرات الـ Lint غير المؤثرة**: وجود بعض متغيرات الأيقونات غير المستخدمة واستخدام `<img>` العادي في بعض الأماكن بدلاً من `<Image />` من Next.js.

### 2.2 نقاط الضعف الأمنية الحالية (Security Considerations for Production)
1. **تسجيل الدخول الوهمي (Mock Auth)**: الدخول يتم بفحص نص الإيميل عبر `setTimeout` بدون تشفير أو فحص كلمة السر الحقيقية.
2. **غياب الـ Server-Side Authorization**: يستطيع أي شخص كتابة الرابط `/demo` أو `/staff` في المتصفح والدخول بدون التحقق من صلاحيته.
3. **حساب المبالغ من جهة العميل (Client-Side Totaling)**: يتم احتساب مبلغ الفاتورة في هاتف الزبون؛ يجب نقل الحساب النهائي للسيرفر قبل اعتماده في قاعدة البيانات.

## 3. قائمة الأولويات والـ Refactoring المقترح

1. **الخطوة الأولى**: إنشاء اتصال Supabase واستيراد جداول الـ SQL وتفعيل قنوات الـ Realtime (P0).
2. **الخطوة الثانية**: كتابة Server Actions لعمليات السلة والتذاكر مع التحقق الأمني من الأسعار (P0).
3. **الخطوة الثالثة**: بناء نظام توكن الطاولات الديناميكي واستوديو طباعة أكواد الطاولات PDF (P1).
4. **الخطوة الرابعة**: تفعيل دخول موظفي المطبخ برمز PIN السريع (P1).
